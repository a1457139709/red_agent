你的判断是对的：当前设计**安全但僵硬**。它把 `Session = 单目标` 写死了，适合 HTB 单机靶场，但不适合真实 CTF/内网靶场里的“发现新资产 → 验证 → 纳入范围 → 继续枚举”闭环。

我建议改成：

# 改良方案：从「Session 单目标」升级为「Scope 驱动的 Campaign」

核心变化：

```text
Project / Campaign
  ├── ScopePolicy 授权范围
  ├── Targets 目标资产池
  ├── Sessions 针对单资产的执行上下文
  ├── Findings 发现
  └── Agent Runs 自动化任务
```

不要再让 Session 承担“边界定义”的职责。

---

## 1. 新模型：Campaign Scope

把边界从：

```text
active_session.target_value == scan_target
```

改成：

```text
scan_target ∈ campaign.scope_policy
```

例如：

```yaml
campaign_scope:
  allowed_hosts:
    - 10.10.10.45
  allowed_cidrs:
    - 10.10.10.0/24
  allowed_domains:
    - forge.htb
  allowed_subdomain_patterns:
    - "*.forge.htb"

  denied_targets:
    - 10.10.10.1
    - metadata.google.internal
    - 169.254.169.254

  allowed_ports:
    - 1-65535

  allowed_protocols:
    - http
    - https
    - tcp

  allowed_tool_categories:
    - recon
    - enum
    - vuln_scan

  require_confirmation_for:
    - exploit
    - credential_use
    - persistence
```

这样一个 Campaign 可以覆盖：

* 单 IP
* 多 IP
* CIDR
* 域名
* 子域名
* 多端口
* 多协议

---

## 2. 新资产发现流程：Discovery Admission

Agent 发现新资产时，不应该直接加入目标，也不应该直接拒绝。

应该走一个中间流程：

```text
Agent 发现资产
    ↓
normalize target
    ↓
ScopeValidator 判断
    ↓
结果：
  1. in_scope      → 自动加入 Target Pool
  2. maybe_scope   → 进入 Pending Review
  3. out_of_scope  → 拒绝并记录
```

例如：

```text
发现：dev.forge.htb
判断：匹配 *.forge.htb
动作：自动加入 Target Pool

发现：10.10.10.46
判断：匹配 10.10.10.0/24
动作：自动加入 Target Pool

发现：evil.com
判断：不匹配任何授权范围
动作：拒绝，不执行扫描
```

---

## 3. Target Pool：目标资产池

新增一个核心表：

```text
targets
```

字段建议：

```text
id
campaign_id
value
type              # ip / domain / url / cidr
normalized_host
source            # user_added / agent_discovered / imported
status            # active / pending / rejected / archived
confidence
discovered_by
discovered_from
created_at
scope_reason
```

示例：

```text
10.10.10.45      active    user_added
10.10.10.46      active    agent_discovered
dev.forge.htb    active    matched *.forge.htb
outside.com      rejected  outside scope
```

---

## 4. Session 重新定义

Session 不再等于授权范围。

Session 应该变成：

```text
Session = 针对某个 Target 的当前操作上下文
```

例如：

```text
Campaign: HTB Forge
  Target Pool:
    - 10.10.10.45
    - dev.forge.htb
    - 10.10.10.46

  Sessions:
    - session-1 → 10.10.10.45
    - session-2 → dev.forge.htb
```

Agent 可以在 Campaign 内切换目标，但每次执行工具时仍然必须经过 ScopeValidator。

---

## 5. Agent 工具层改良

不要让 LLM 直接传任意目标。

但可以允许它传：

```text
target_ref
```

而不是裸 target。

例如：

```python
start_port_scan(target_id="target_123")
start_dir_scan(target_id="target_456", path_wordlist="common")
start_poc_scan(target_id="target_789", template_set="safe")
```

禁止：

```python
start_port_scan(target="1.2.3.4")
```

这样模型不能随便构造目标，只能选择已经通过 admission 的目标。

---

## 6. 允许 Agent 提交“新增目标申请”

新增高层工具：

```python
propose_target(value, source, evidence_id=None)
```

流程：

```text
Agent 发现新资产
    ↓
调用 propose_target
    ↓
ScopeValidator 判断
    ↓
in_scope 自动加入
maybe_scope 等待人工确认
out_of_scope 拒绝
```

返回示例：

```json
{
  "status": "accepted",
  "target_id": "target_123",
  "reason": "matched allowed domain pattern *.forge.htb"
}
```

或者：

```json
{
  "status": "pending_review",
  "reason": "new IP 10.10.10.46 is not explicitly listed but inside related subnet"
}
```

---

## 7. ScannerService 改良

当前是：

```text
task.target_host == session.target_value
```

建议改成：

```text
task.target ∈ campaign.scope_policy
AND
task.target_id exists in target_pool
AND
target.status == active
```

也就是双重校验：

```text
1. Target 必须在目标池
2. Target 必须符合 ScopePolicy
```

这样即使有人绕过 Agent 调 API，也不能扫越界目标。

---

## 8. 推荐执行链路

```text
User 创建 Campaign
    ↓
配置 ScopePolicy
    ↓
添加初始 Target
    ↓
Agent 开始 Recon
    ↓
发现新资产
    ↓
propose_target()
    ↓
ScopeValidator admission
    ↓
加入 Target Pool / Pending Review / Reject
    ↓
Agent 针对 active targets 创建任务
    ↓
ScannerService 二次校验
    ↓
执行扫描
```

## 最终结论

你现在的设计：

```text
Session = Target = Scope
```

应该改成：

```text
Campaign = Scope
Target Pool = 被授权资产集合
Session = 单目标执行上下文
Agent = 只能操作 active targets
ScannerService = 最终 admission gate
```

这是更适合 AI CTF Agent 的模型。它既保留边界安全，又支持动态发现、多目标、子域名、CIDR 和人工确认。
